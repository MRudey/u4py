u4py.analysis.inversion module

Inversion of timeseries data

A timeseries is defined as a three component velocity field and analyzed through an inversion approach with up to eleven different components. The data has to be in dictionary format and may include errors for each component:

data = {
“t”: NumPy array of time in float years (e.g. 01.01.2014 = 2014.0),
“dataE”: NumPy array of E-W component (mm),
“dataN”: NumPy array of N-S component (mm),
“dataU”: NumPy array of Up-Down component (mm),
“sigmE”: NumPy array of Error of E-W component (mm),
“sigmN”: NumPy array of Error of N-S component (mm),
“sigmU”: NumPy array of Error of Up-Down component (mm),
“station”: String of station name,
}

Examples: An implementation using test data is found in invert_test_data(). A best practice to work with real data is implemented in u4py.analysis.processing.invert_file().

Source: This code has been transcribed from the Matlab source code of S. Metzger, GFZ-Potsdam.

This function creates a hypothetical dataset with a single earthquake which can be used to test the inversion algorithm if it works the same as the original Matlab source.

The dataset covers the time from 01.01.2007 to 01.01.2015 in intervals of roughly one day. A simulated earthquake is generated on 27.02.2010 at 00:56h. The synthetic dataset contains:

  • A linear component,

  • two annual (sine/cosine, \(\frac{\pi}{2}\)),

  • two semiannual components (sine/cosine, \(\frac{\pi}{4}\))

  • a heavyside step function with several mm of displacement and post seismic decay,

  • Gaussian noise.

Inversion Theory

The problem must be linear, otherwise you cannot invert!

The measured data \(d\) is the result of the multiplication of a Green’s function matrix \(G\) and the model parameters \(m\), i.e., the components:

\[d = G \cdot m\]

(d: data, G: solver matrix, m: model parameters)

To invert for the model parameters the inverse product of the solver matrix with its transposed version \((G'\cdot G)^{-1}\) is multiplied by transposed solver matrix \(G'\) and the measured data \(d\):

\[m = (G'\cdot G)^{-1} \cdot G' \cdot d\]

and, using weights \(W\):

\[W \cdot d = W \cdot G \cdot m\]
\[m = (G' \cdot S^{-1} \cdot G)^{-1} \cdot G' \cdot S^{-1} \cdot d\]

with \(S^{-1} = W' \cdot W\), or, simplified: \(S = s^2\)

Setup of the G-Matrix

The full G-Matrix contains a linear trend, offset, oscillation and a postseismic signal:

\(A_1 + A2\cdot(t-t_R) + A_3 \cdot (t-t_R)^2 + \dots\)
\(B_1 \cdot sin(2 \pi t) + B_2 \cdot cos(2 \pi t) + \dots\)
\(B_3 \cdot sin(4 \pi t) + B_4 \cdot cos(4 \pi t) + \dots\)
\(C_1 \cdot tH(t_{AT}) + C_2 \cdot tH(t_{EQ}) + \dots\)
\(D_1 \cdot log(1+\frac{t}{dT_1} + D_2 \cdot log(1+\frac{t}{dT_2})\)

In this equation, the following model parameters are included:

  • \(A_1 \dots A_3\): General offset and steady rate (can be steady, linear , for interseismic deformation, or quadratic, for GIA adjustment)

  • \(B_1 \dots B_4\): Amplitudes of annual and semi-annual oscillations

  • \(C_1 \dots C_2\): Amplitude of Heaviside function (\(d_{EQ}\) or \(d_{AT}\)) starting at \(t_{AT}\) or \(t_{EQ}\).

  • \(D_1 \dots D_2\): Amplitude of postseismic signal starting at \(t_{EQ}\).

The G-Matrix needs to be individualized for each station, depending if it is affected by these signals. You should create a GLOBAL G-Matrix including ALL stations and not solve this for each single station. You do that by concatenating all stations and components into one big G-Matrix.
